# Lanta Camera Proxy — Документация (v2.1.0)

Прокси-сервер для камер видеонаблюдения и домофонов провайдера **ЛанТа** (`mobile.lanta-net.ru`) с авторизацией по звонку или токену.

Версия **2.1.0** добавляет интеграцию домофона через **MQTT Auto-Discovery**: устройство
«Домофон LanTa» появляется в Home Assistant автоматически, без правки `configuration.yaml`.

---

## 1. Установка

1. Скопируйте папку `lanta-cam-proxy` в каталог надстроек Home Assistant
   (обычно `/addons/lanta-cam-proxy`).
2. В Home Assistant: **Настройки → Дополнения → Магазин дополнений → ⋮ → Локальные дополнения**.
3. Обновите список и установите **Lanta Camera Proxy**.
4. Во вкладке **Конфигурация** настройте параметры (см. ниже) и запустите.

---

## 2. Параметры конфигурации

| Параметр | Тип | По умолч. | Описание |
|----------|-----|-----------|----------|
| `phone` | str? | `""` | Номер договора ЛанТа (`79001234567`). Можно ввести позже на `/auth`. |
| `bearer_token` | str? | `""` | Готовый токен (UUID без `Bearer`), если не хотите вход по звонку. |
| `house_id` | str? | `""` | ID дома (несколько через запятую). Оставьте пустым для автоопределения. |
| `flat_id` | str? | `""` | ID квартиры. Оставьте пустым для автоопределения. |
| `refresh_interval` | int | `5400` | Интервал обновления ссылок камер (сек). |
| `plog_poll_interval` | int | `7` | Интервал опроса журнала событий домофона (сек). |
| `dedup_window` | int | `180` | Окно группировки одного прохода (двор→подъезд→лифт), сек. |
| `mqtt_host` | str? | `""` | Адрес MQTT-брокера. Пусто = взять автоматически у Supervisor. |
| `mqtt_port` | int? | `1883` | Порт MQTT. |
| `mqtt_user` | str? | `""` | Логин MQTT. |
| `mqtt_pass` | password? | `""` | Пароль MQTT. |

> Параметры MQTT (`mqtt_host`, `mqtt_port`, `mqtt_user`, `mqtt_pass`) можно не заполнять —
> надстройка забирает настройки брокера у Supervisor автоматически
> (должна быть включена интеграция/дополнение **MQTT**).

---

## 3. Авторизация

1. Откройте веб-интерфейс:
   ```
   http://<IP_ВАШЕГО_HA>:8199/auth
   ```
2. **Вход по звонку:**
   - Введите номер телефона и нажмите **«1. Запросить звонок»**.
   - Позвоните с этого номера на **`8 800 222-06-68`** и дождитесь автосброса.
   - Нажмите **«2. Я позвонил — получить токен»**.
3. Либо вставьте готовый токен в поле «Способ 2» и нажмите **Сохранить**.

Статус «Токен: ДА» и число камер вверху страницы подтверждают успех. Токен хранится
в `/data/lanta_auth.json` и переживает перезапуск.

---

## 4. Настройка имён людей (страница `/people`)

Чтобы домофон показывал, **кто именно пришёл**, задайте имена:

1. Откройте:
   ```
   http://<IP_ВАШЕГО_HA>:8199/people
   ```
2. Страница автоматически подтягивает:
   - **Лица** — эталонные фото из `/api/frs/listFaces` (картинки проксируются через `/face_img/...`, без проблем CORS/SSL);
   - **Ключи/брелоки** — RFID-ключи, найденные в журнале (`event == "3"`);
   - **Телефоны** — номера из `getSettingsList` (`roommates`).
3. Впишите имена напротив нужных `faceId`, ключей и телефонов и нажмите **Сохранить имена**.

Имена сохраняются в `/data/lanta_people.json` в формате:
```json
{
  "faces": {"320080": "Иван"},
  "keys": {"0000006E12CD98": "Иван"},
  "phones": {"79001234567": "Иван"}
}
```
Один человек может иметь несколько `faceId` (разные ракурсы) — присвойте всем одно имя.

## 5. Интеграция MQTT (автоматически)

После запуска надстройка публикует конфиги MQTT Auto-Discovery (с префиксом `homeassistant/`,
`retain=True`). В Home Assistant появится устройство **«Домофон LanTa»** со следующими сущностями:

| Тип | Сущность | Назначение |
|-----|----------|-----------|
| `switch` | Гостевой доступ (1 час) | Включить/выключить автооткрытие двери. |
| `switch` | Трубка в квартире (КМС) | Включить/выключить аналоговую трубку (ночной режим). |
| `switch` | Видеозвонки в приложение | Включить/выключить видеозвонки в приложение. |
| `switch` | Вход по коду | Разрешить/запретить открытие по коду. |
| `sensor` | Последнее событие домофона | Текст последнего события + атрибуты (uuid, person, is_known, door и т.д.). |
| `binary_sensor` | Открытие по коду | `ON` на 15 сек при открытии по коду. |
| `binary_sensor` | Звонок в домофон | `ON` на 15 сек при звонке. |
| `binary_sensor` | Статус токена LanTa | `OFF` — токен валиден, `ON` — ошибка `401`/нет токена. |
| `camera` | Домофон LanTa Последний кадр домофона | JPEG последнего кадра события (для карточки и пуш-уведомлений). |

Правка `configuration.yaml` **не требуется**. Если брокер перезапустится, надстройка
автоматически переподключится и заново опубликует Discovery-конфиги.

## 6. Пример: пуш-уведомление на iPhone с фото

Автоматизация в Home Assistant (UI → **Автоматизации → Создать** или через YAML):

```yaml
alias: "Кто пришёл — уведомление с фото"
description: "Пуш на iPhone при событии домофона"
mode: single
triggers:
  - trigger: state
    entity_id: sensor.poslednee_sobytie_domofona
    not_to:
      - unknown
      - unavailable
conditions:
  - condition: template
    value_template: >
      {{ not state_attr('sensor.poslednee_sobytie_domofona', 'is_duplicate_pass')
         and state_attr('sensor.poslednee_sobytie_domofona', 'is_known') }}
actions:
  - action: notify.mobile_app_iphone
    data:
      title: "Домофон LanTa"
      message: >
        {{ state_attr('sensor.poslednee_sobytie_domofona', 'person') }}
        — {{ state('sensor.poslednee_sobytie_domofona') }}
        ({{ state_attr('sensor.poslednee_sobytie_domofona', 'door') }})
      data:
        image: /api/camera_proxy/camera.domofon_lanta_poslednii_kadr_domofona
        entity_id: camera.domofon_lanta_poslednii_kadr_domofona
```

> `camera.domofon_lanta_poslednii_kadr_domofona` — сущность камеры «Домофон LanTa Последний
> кадр домофона». Если имя сущности у вас отличается, укажите фактический `entity_id` камеры.
> Условие отсекает серию дублей одного прохода (`is_duplicate_pass`) и неизвестных
> (`is_known = false`), чтобы не слать спам от соседей и курьеров.

## 7. Подключение камер к go2rtc

1. Откройте готовый список потоков:
   ```
   http://<IP_ВАШЕГО_HA>:8199/go2rtc.yaml
   ```
2. Скопируйте блок `streams:` в конфигурацию надстройки **go2rtc** и перезапустите её.
3. Добавьте камеры через WebRTC Camera (`url: cam_<id>`) или Generic Camera (`rtsp://<IP>:8554/cam_<id>`).

---

## 8. HTTP-эндпоинты (порт `8199`)

| Путь | Метод | Описание |
|------|-------|----------|
| `/auth` | GET | Авторизация по звонку или токену. |
| `/people` | GET | Настройка имён (лица/ключи/телефоны). |
| `/people/save` | POST | Сохранение имён. |
| `/face_img/{face_id}` | GET | Прокси фото лица из `/api/frs/listFaces`. |
| `/cameras` | GET | JSON-список камер и ссылок на потоки. |
| `/go2rtc.yaml` | GET | Конфиг потоков для go2rtc. |
| `/ts/{cam_id}` | GET | MPEG-TS через ffmpeg. |
| `/stream/{cam_id}/index.m3u8` | GET | Прокси оригинального HLS. |
| `/preview/{cam_id}` | GET | JPEG-скриншот камеры. |
| `/door_events` | GET | Текущее состояние событий и настроек домофона. |
| `/event_preview` | GET | JPEG последнего кадра события. |
| `/guest_access` | GET/POST | Статус/переключение автооткрытия на 1 час. |
| `/refresh` | POST | Принудительное обновление камер. |
| `/debug_api` | GET | Диагностика API (`houseId`, `flatId`). |

---

## 9. Диагностика

- **Камер 0** — проверьте `house_id` через `http://<IP>:8199/debug_api` (поле `houseId`).
- **Устройство не появилось** — убедитесь, что в HA включена интеграция **MQTT** и брокер запущен;
  проверьте лог надстройки на строку `MQTT connected to ...`.
- **Статус токена LanTa = ON** — обновите токен на `http://<IP>:8199/auth`.
